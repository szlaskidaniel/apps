How to configure App Store Server Notifications V2

App Store Connect lets you choose where Apple sends signed purchase events for each app. You need an HTTPS endpoint that accepts Version 2 notifications and access as an Account Holder, Admin, App Manager, or Marketing user. For SoldIt!, copy the webhook URL from the settings for the app you want to monitor.

Set the production destination

  1. Open Apps in App Store Connect and select your app. In the sidebar under General, open App Information.
  2. Find App Store Server Notifications. Check the current Production Server URL. Apple uses one destination per environment, so replacing an existing URL redirects events away from the previous receiver.
  3. For an empty field, click Set Up URL, paste the complete HTTPS address, choose Version 2, and click Save. To update an existing destination after planning the change, use Edit.

Choose where sandbox events go

For a separate test receiver, set the Sandbox Server URL and select Version 2 there as well. If you leave sandbox empty, Apple sends sandbox events to the production URL. Setting only a sandbox URL lets you test while production delivery is unconfigured. Apple’s URL configuration guide

Verify delivery before waiting for a sale

With App Store Server API access, call Request a Test Notification for the environment you configured. Pass the returned testNotificationToken to Get Test Notification Status in the same environment and check the delivery result. If it fails, recheck the saved URL and the receiver’s HTTPS response.

A successful TEST confirms that the endpoint responded. To check the full sale-alert path, look for the next qualifying purchase in SoldIt! and on your iPhone. Apple’s server setup and testing instructions
